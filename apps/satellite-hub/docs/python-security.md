# Python Hub security contract

The Python Hub is a transport adapter. Companion Core and Gateway retain
identity, authorship, policy, prompt assembly, and canonical memory authority.
The bounded Python history is an ephemeral transport cache, not a memory store.

## Listener admission and migration

`AUDIO_SERVER_BIND_HOST` defaults to `127.0.0.1`. Every nonliteral-loopback HTTP
bind, including `0.0.0.0`, `::`, hostnames, and LAN addresses, rejects at startup.
There are two explicit modes:

- Local development: set `HUB_DEVELOPER_MODE=true`, use literal loopback binds,
  and advertise an HTTP literal-loopback origin. This allows local anonymous
  access and provider spending. It cannot advertise remote playback URLs.
- Remote playback: leave developer mode off, set `AUDIO_PUBLIC_BASE_URL` to an
  exact HTTPS origin such as `https://audio.example.test`, and configure a
  dedicated `AUDIO_RELAY_AUTH_TOKEN`. It must be independently generated random
  base64url data, 43–512 characters, and cannot reuse realtime or provider keys.
  No secret is embedded in URLs. Legacy public-host/port settings alone do not
  enable remote playback.

The remote mode requires an operator-owned, same-host relay outside this repo.
It must terminate TLS, authenticate and authorize each satellite/client for its
audio request, strip client-supplied Authorization and forwarding headers, and
inject exactly `Authorization: Bearer <AUDIO_RELAY_AUTH_TOKEN>` on the loopback
hop. Only that relay receives the dedicated token. Constrain its listener,
allowed clients, certificate trust and network exposure in its own configuration.
The Python listener admits only loopback peers with the configured bearer;
forwarding headers never establish trust. Browser Origin is denied. The relay
must apply its own time, size, and connection budgets as well.

An ESPHome player that cannot use authenticated HTTPS does not satisfy this
contract. Direct anonymous LAN HTTP playback is unsupported and must be migrated
to a capable authenticated client/relay arrangement. There is no credential in
path, query, firmware URL, or silent insecure fallback. No relay or device
configuration is provisioned by this change.

Files are registered under opaque `/files/<random-id>` routes. Source filenames,
directories, indexes, and unregistered files are unavailable. Streams use opaque
`/streams/<random-id>` routes and admit one consumer. Every request requires
authentication in relay mode, including HEAD. Queries and credential-bearing
URLs reject. Symlinks, hardlink aliases, nonregular files and escaping paths
reject; reads repair owned file permissions before serving.

## Resource defaults

Python realtime has one aggregate TCP budget: `max_connections` (64 by default)
is the ceiling for both total sockets and pending handshakes. Every accepted TCP
connection reserves a slot synchronously in the production `create_connection`
factory, before reading headers or evaluating credentials. A full budget closes
excess TCP sockets immediately, without creating a WebSocket handler or reading
their request. Authentication retains the same slot; it cannot open a transfer
window or expand the authenticated limit. The slot is released only on TCP
connection loss, including denial, malformed input, timeout and normal/abrupt
close. No per-connection watcher task is used for accounting.

The absolute opening handshake deadline stays five seconds; header progress does
not extend it. Shutdown stops admission, aborts pending handshakes immediately,
and awaits the WebSocket server's handlers and TCP cleanup. Open WebSockets use
the existing five-second close deadline. Neither admission nor rejection logs
request content, headers, peer addresses or credentials.

All `AUDIO_*` capacities are positive integers; seconds are positive finite
numbers. Invalid settings fail startup. The complete listener reads these values
from the CLI-created runtime configuration.

| Environment setting | Default | Enforcement |
| --- | ---: | --- |
| `AUDIO_MAX_REQUESTS` | 16 | Admission before creating a request thread; excess sockets receive 503 |
| `AUDIO_MAX_HEADER_BYTES` | 8192 | Request line plus headers; overflow receives 431 |
| `AUDIO_HEADER_TIMEOUT_SECONDS` | 5 | Absolute deadline, including slowly dripping partial headers |
| `AUDIO_IO_TIMEOUT_SECONDS` | 5 | Socket read/write idle deadline |
| `AUDIO_RESPONSE_TIMEOUT_SECONDS` | 120 | Absolute response deadline; one request per connection |
| `AUDIO_MAX_RESPONSE_BYTES` | 16777216 | Static file and total generated bytes per stream |
| `AUDIO_MAX_FILES` | 128 | Registered opaque file references; excess registration raises a static capacity error |
| `AUDIO_FILE_TTL_SECONDS` | 300 | Reference expires from registration, independently of disk retention |
| `AUDIO_MAX_STREAMS` | 16 | Includes streams never fetched or still being produced |
| `AUDIO_MAX_STREAM_CHUNKS` | 64 | Queued chunks per stream |
| `AUDIO_MAX_STREAM_BYTES` | 1048576 | Queued bytes per stream |
| `AUDIO_STREAM_MAX_AGE_SECONDS` | 120 | Absolute stream lifetime |
| `AUDIO_STREAM_IDLE_SECONDS` | 15 | Consumer progress deadline; producer writes do not renew it |

Stream writes never wait for an absent or slow consumer. Overflow aborts and
clears the stream with a stable `RuntimeError`; later writes also fail. Closing
a producer uses no reserved queue slot and never blocks. Finished streams drain
normally; aborted/expired streams close without a false successful terminator.
The listener reaps registries at 50 ms intervals and checks expiry on access;
shutdown aborts buffers, closes active sockets and joins the listener thread.
Public library users can also invoke `purge_expired()` when no listener runs.

`SESSION_MAX_SESSIONS=128` caps the session cache. `SESSION_TTL_SECONDS=300` is
an idle TTL: a successful get, get-or-create or touch renews recency and idle time.
Expiry is inclusive at the deadline; admission evicts the least recently used
entry after removing expired entries. Active/recent sessions retain their own
history, and evicted/reset sessions do not inherit another session's context.

The model adapter uses `HUB_HISTORY_MAX_CONVERSATIONS=128`,
`HUB_HISTORY_TTL_SECONDS=300`, `HUB_HISTORY_MAX_MESSAGES=64`, and
`HUB_HISTORY_MAX_BYTES=65536`. These cap stored context and outgoing message
context. Old messages are removed as whole messages; a retained suffix starts
with a user message, never an orphan assistant reply. UTF-8 content bytes count
toward the budget. A single oversized input rejects before HTTP/provider use;
an oversized reply fails without persisting partial history. Streaming reply
accumulation is bounded by the same byte budget. Empty completions fail explicitly
and never synthesize developer-authored companion speech. `SessionCache` also
caps history at 64 messages and 65536 UTF-8 bytes by default; library callers can
inject smaller constructor limits for either store.

Provider receive paths enforce limits before buffering or JSON/base64 parsing.
The model wire budget is `8 * HUB_HISTORY_MAX_BYTES + 65536` bytes per response;
each SSE line is limited to `6 * HUB_HISTORY_MAX_BYTES + 8192` bytes, allowing
JSON escaping overhead. Body and line limits are checked incrementally, including
chunked transfers. Compressed response bodies reject; requests advertise identity
encoding. Oversized responses clear/fail the operation without caching history
or writing an audio artifact. Model calls also have an absolute request deadline
(60 seconds by default); batch STT/TTS calls have a 120-second absolute deadline.

The STT/TTS adapters share finite production defaults in `ProviderLimits`:
16 MiB HTTP/audio aggregates, 256 KiB JSON/voice-list bodies, 1 MiB WebSocket
messages, four queued WebSocket frames, 16 TTS contexts per provider, 64 queued
audio chunks and 1 MiB queued audio per context, 65536 UTF-8 text/transcript bytes,
128 final transcript segments, a 15-second TTS consumer idle deadline and a
120-second context age deadline. A reserved terminal queue slot prevents close
or overflow from blocking behind a slow consumer. Invalid/over-budget upstream
frames fail affected consumers, clear their buffers, and allow the next operation
to reconnect or reuse a healthy connection. TTS context expiry runs even while a
consumer is abandoned. Deepgram turns disconnect after finalization; its existing
2.5-second finalize deadline now fails explicitly instead of returning incomplete
data. Constructors accept smaller injected budgets and local provider URLs for
system-boundary tests; runtime defaults stay finite.

Both streaming provider clients install `ProviderClientConnection` in the real
WebSocket connection factory. It uses the listener's shared `RealtimeOutput`
owner before frame serialization, covering binary/text data, fragments,
automatic pongs, explicit ping/pong and close. Per socket, the defaults are 8,192
retained frames, 1,048,576 bytes and a five-second absolute completion deadline.
Each frame reserves its payload plus the maximum 14-byte RFC 6455 header;
native asyncio output and pending protocol writes share the byte cap without an
additional overshoot allowance. TLS counts both the SSL/BIO output and underlying
TCP buffer. Each frame also reserves up to 2,053 bytes of TLS record header and
expansion per 16,384 plaintext bytes, within the same byte ceiling. The explicit
CPython asyncio SSL transport seam fails closed if its underlying buffer cannot
be inspected; an alternate event loop must provide that seam before use.
HTTP handshake output also passes the byte cap.
Compression is disabled. Kernel TCP buffers, source objects and inbound queues
are separate from this output budget.

Partial drain and new frames do not extend the deadline. Output overflow,
expiry or write failure aborts only that provider socket, discards pending
results, and retains its charge until TCP loss. Reader, Deepgram keepalive and
TTS sender tasks settle before provider cleanup completes. A canceled shutdown
caller leaves one shielded cleanup task for subsequent callers to join. The last
TTS context closes its socket; overlapping contexts retain their shared socket
until their own completion or a socket failure. Context cleanup serializes final
removal and the last-socket decision. Pending handshake work is canceled and its
TCP loss is awaited before provider shutdown returns. Fresh streams reconnect after
settlement. Python has no separate global provider-work counter; these lifecycle
rules preserve its per-turn and context ownership. TypeScript global provider
admission is unchanged. Local regression peers reduce TCP buffers and exercise
legal ping floods, application/control competition, exact and one-over limits,
deadlines, write errors, cancellation, repeated shutdown and fresh recovery.
Live provider and sustained live-load validation remain pending.

## Private artifacts and diagnostics

Runtime files are confined beneath a reserved `.hub-artifacts-v1` directory in
each configured artifact/audio root. Roots must be dedicated directories; home,
working/project directories, their ancestors, and filesystem roots reject.
Turn, interaction and announcement directories use random IDs, never raw
conversation IDs or content. PCM/WAV, provider audio, transcripts, replies,
events, interactions, transport manifests and probe captures use the shared
artifact writer. It walks each directory by descriptor without following links,
rejects `..`, sibling-prefix escapes, intermediate/final symlinks and hardlinks,
repairs owned directories to 0700 and regular single-link files to 0600, and
atomically replaces complete files. Appends and reads use the same checks.
Files have a 16 MiB default write/read/append cap (audio serving uses its explicit
response budget). A shared namespace lock serializes cleanup and writes across
instances in one process.

`HUB_ARTIFACT_RETENTION_HOURS=24` is validated within 1–168 hours. Cleanup removes
expired Hub-owned formats inside the reserved namespace, using last-modified
time; it preserves fresh files, unrelated names, symlinks and hardlink aliases.
Interactions and announcements have individual immutable event files so ongoing
traffic does not retain old entries indefinitely. Startup and shutdown run
cleanup. One runtime maintenance owner checks both main and audio namespaces
every 60 seconds, including while idle, and is canceled/awaited during shutdown,
including any cleanup already in progress. Transport capture has the same
maintenance lifecycle. Cleanup failures emit a static diagnostic. Library users
must schedule cleanup or call `close()` themselves.

An explicitly selected `hub probe --output-path` is an operator export: it is
written atomically with 0600 permissions and link checks, but never triggers
retention over its parent or siblings. Its later disposal is operator-owned.
Old unnamespaced artifacts are not automatically imported or deleted; migrate
or dispose of them explicitly outside Git before relying on the new policy.

Python logging is content-free at every level. The process installs its policy
before adapter imports: only known static Hub events reach logging transports;
dynamic arguments, exception/stack text, source paths and third-party prose are
discarded before formatting. Dependency diagnostics retain severity as static
events. CLI startup, reconnection, interaction and probe output contains no
names, URLs, provider replies, credentials or exception details. This policy
also applies if the Python package is embedded in another Python process.
There is no content-bearing debug/break-glass mode.

## Complete utterances

Python realtime acknowledges `turn.start`, validates and bounds PCM frames, and
only admits a complete, nonempty utterance to STT and the companion after
`turn.end`. It emits `transcript.final`; interim transcript delivery is currently
unavailable. Empty input yields a structural no-input event. Invalid or oversized
traffic produces no partial artifact or provider admission. Reply deltas remain
companion/provider-authored; interruption and failures are structural events,
not invented companion speech.

Validation uses the locked Python environment (`uv sync --frozen --group dev`)
and `npm run verify:satellite-hub` from the repository root. Tests use invented
content, real local sockets and real temporary files; no live device or paid
provider is contacted.
