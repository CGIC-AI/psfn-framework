# Purrsephone Substrate Framework (PSFN) Analysis Report

**Date:** Saturday, February 14, 2026  
**Status:** Comprehensive Review Complete

## 1. Open Loops & Integration Gaps
*   **Dormant Gateway Capabilities:** The `web.fetch`, `fs.read`, and `fs.write` RPC methods are fully implemented and hardened in the Gateway but are not exposed as tools to the `AgentLoop` or injected into the `REPLSandbox`. Purrsephone currently lacks the ability to reach the web or the workspace filesystem.
*   **Split-Mode Parity:** The hourly "Discord heartbeat" (proof-of-life pulse) is implemented in `src/runtime.ts` but missing from `src/agent-main.ts`. In production (split mode), this feature is currently absent.
*   **REPL Context Blindness:** The `REPLSandbox` provides `session_messages(channelId)`, but the current `channelId` is not made available to the reasoning engine as a global or via the system prompt, making it difficult for the agent to query its own recent history programmatically.
*   **Unused Salience Reinforcement:** `MEMORY_CONFIG.salienceBumpOnAccess` is defined but never called in `MemoryRetriever`. Memories only decay over time; they are never "strengthened" by the act of being remembered (only by being deduplicated during writes).

## 2. Security Assessment
*   **Admin CSRF:** The Admin GUI (`src/channels/admin/server.ts`) uses cookie-based authentication but lacks CSRF tokens. This exposes the `/api/settings` and `/api/memory` endpoints to cross-site request forgery.
*   **Sandbox Weakness:** The `node:vm` usage in `src/repl/sandbox.ts` is vulnerable to escapes. While mitigated by Docker isolation in production, it remains a risk for single-process development or host-direct deployments.
*   **Embedding Schema Rigidity:** `MemoryStore` uses `CREATE VIRTUAL TABLE IF NOT EXISTS` for embeddings. If the embedding model or dimensions change in `.env` after initialization, the database schema will not update, causing runtime failures.

## 3. Critical Logic Bugs
*   **Double-Decay Salience:** `SalienceDecay.run()` calculates decay using `Math.exp((-Math.LN2 * dt) / halflife)` where `dt` is the total time since last access, but it applies this factor to the *already decayed* salience stored in the DB every minute. This causes memories to evaporate exponentially faster than their defined half-lives.
*   **Context Truncation:** `SessionManager.entriesToMessages` merges consecutive same-role messages but drops the very first message if it is from the assistant (to satisfy some LLM API requirements). This can lead to losing the start of a conversation if it began with an assistant greeting.

## 4. Redundancy & Clutter
*   **Init Duplication:** Setup logic for the scheduler, tools, and shard manager is duplicated across `src/runtime.ts` and `src/agent-main.ts`.
*   **Shard Session Pollution:** Ephemeral shards create persistent JSONL session files in `data/sessions/` for every execution. These are never cleaned up, leading to L0 archive bloat.

## 5. Optimizations & Improvements
*   **Memory Pruning:** There is currently no "Garbage Collection" for memories. Memories that hit the `salienceFloor` should be deleted or archived to prevent unbounded SQLite growth.
*   **Config Inconsistency:** Embedding settings (Ollama URL, Model, Dims) are read directly from `process.env` in the runtime setup and are not part of the `SubstrateConfig` or the live-editable settings in the Admin GUI.
*   **Vector Search + FTS5:** Retrieval relies purely on `sqlite-vec`. Adding SQLite's FTS5 for keyword-based search would significantly improve retrieval for specific named entities or rare terms.
